## 가장 중요한 발견 — 음성 정확도 문제의 진짜 원인

이번 세션에서 가장 공들여 판 주제입니다. 결론이 두 번 바뀌었습니다.

1. **1차 결론(기각됨)**: "한국어(kss)만 TTS→STT 왕복 정확도가 낮다" → 베트남어도
   부분적으로 낮다는 걸 확인하며 "mimic3 계열(ko, vi) 모델 전체의 문제"로 수정.
2. **2차 결론(기각됨)**: 13개 언어 전부를 실측한 결과, 로마자 언어(es/fr/de/ru/it/pt/pl 등)는
   TTS 계열과 무관하게 거의 다 완벽했고, **비라틴 문자 언어(한국어/아랍어/힌디어)만
   급락**한다는 패턴으로 정정.
3. **3차 결론(현재, 가장 근거가 탄탄함)**: whisper 모델을 base→small로 바꿔 대조 실험한
   결과, **언어별로 원인이 다르다**는 게 확정됐습니다.
   - **힌디어**: 유사도 0.17(base) → 0.67(small)로 4배 개선 — **whisper 모델 크기가 원인**.
   - **아랍어**: 0.80(base) → 0.77(small)로 거의 무변화 — 모델 크기와 무관, 다른 원인.
   - **한국어**: 0.24(small)로 거의 개선 없음 — 힌디어와 정반대. **TTS(kss) 자체의 음질/
     발음 문제**라는 기존 가설이 가장 유력한 설명으로 남음.
   - **구조적 뒷받침**: 다른 모든 언어는 `_medium` 등급 TTS 모델을 쓰는데 한국어만
     선택의 여지 없이 `_low` 등급을 씁니다 — 등급 차이가 음질에 직결된다는 건 VITS 계열의
     일반 상식이라, 이게 가장 설득력 있는 구조적 설명으로 남았습니다.

**실용적 결론**: 온보딩 안내 문구를 이 최신 패턴에 맞게 갱신했습니다(한국어/아랍어/힌디어
선택 시 안내, 힌디어는 특히 강조). STT 기본 모델 교체(base→small)와 Supertonic TTS 교체는
둘 다 "큰 결정"이라 보류했습니다.

## 코드에서 실제로 고친 것

- **`.gitignore`**: `.claude/voice-settings.json`이 빠져 있어 테스트로 온보딩된 상태가
  그대로 커밋될 뻔한 걸 발견·수정.
- **`voice/tts.py`**: `synthesize()`의 타입힌트(`tuple[np.ndarray, int]`)와 실제 반환값
  (list)이 어긋나던 걸 `np.asarray()`로 정정, 실제 모델 호출로 재확인.
- **`voice/inject.js`**: `socket.write()` 직후 바로 소켓을 닫아 데이터가 잘릴 수 있던
  위험을 콜백 방식으로 수정, 로컬 named pipe로 왕복 재검증.
- **`voice/listener.py`**: `lwake.listen()`이 참조 파일 손상 시 조용히 무한 루프를 도는
  잠재 경로를 정적 리뷰로 발견해 로그+재시도 방어 코드 추가.
- **`.claude/download_tts_model.py`**: `tarfile.extractall()`에 안전 필터(`filter="data"`)
  추가 — tar 경로 탈출 취약점 계열 방지, 재다운로드로 회귀 없음 확인.
- **`.claude/verify.cmd`**: import 체크에 빠져 있던 `voice.languages`/`voice.stt`/
  `voice.vad`/`voice.wakeword` 4개 모듈 추가.
- **`.claude/verify_routing.py`**: 다중 세션 라우팅 규칙(①②③, active 필터링)을 상시
  회귀 테스트로 승격 — 이전엔 수동 검증만 있었음.
- **`.claude/skills/voice-on/SKILL.md`**: 온보딩 안내 문구를 최신 실측 패턴(한국어/아랍어/
  힌디어)에 맞게 갱신.

## 서드파티 라이브러리에서 발견한 것 (우리 코드엔 영향 없음, 문서화만)

- **`lwake`(local-wake)**: 임베딩 모델이 패딩 안 된 짧은 오디오(0.775초 미만)에서
  크래시함을 재현·원인 확정(`MIN_SAMPLES` 상수 발견). 우리 `WakeWordDetector`는 항상
  패딩되는 경로만 써서 영향 없음을 확정.
- **whisper(pywhispercpp)**: 완전한 무음에서도 `'[두 번째]'` 같은 환각 텍스트를 만들어냄.
  신뢰도 필드(`probability`)로 걸러보려 했으나 이 버전에서 항상 `nan`이라 못 씀을 확인 —
  다음에 실제 마이크 검증할 때 사용자와 필터링 방식을 논의해야 할 항목으로 남김.

## 경쟁 프로젝트(Heard) 심화 조사

Heard(github.com/heardlabs/heard)의 실제 README를 재조사해 두 기능을 설계 스케치로
남겼습니다(코드 변경 없음, 채택 여부는 큰 결정):

1. **"Catch me up"** — 자리 비운 동안 여러 세션의 이력을 나중에 몰아서 재요약해 듣는 기능.
2. **Listening modes**(Co-pilot/Companion/Focus) — 상황별 알림 상세도 조절.

또한 Heard의 "narration brain"(중앙 판단자가 다중 세션 우선순위를 판단하는 구조)이
과거 우리가 기각만 하고 넘겼던 B안과 일치한다는 교차 연결도 확인했습니다.
